# lhg-tb-review：数据复盘

## 1. 何时使用

- 每周/每月固定复盘，看店铺哪里出了问题时
- 流量掉了、转化掉了，想定位原因时
- 活动结束后，总结这次做对了什么、做错了什么时

**诚实边界**：复盘只做归因与建议，不编造数据、不承诺"改完流量翻倍"。

## 2. 输入与输出

**输入**：用户提供的**真实后台数据**（生意参谋/千牛）：曝光量、点击率、转化率、客单价、退货率。**没有真实数据就直说做不了归因，不许编、不许估计。**

**输出**：复盘报告——数据快照 → 漏斗定位 → 归因 → 改进行动（1-3 条）→ 下期验证指标。

## 3. 分步方法论

### 第 1 步：对齐数据口径

- 问清周期（周/月）、对比基线（上周/上月/活动前）
- 数据缺失就标"待补"，不许用"大概"糊弄
- 只看自己后台的数据，不拿"听说"当依据

### 第 2 步：漏斗定位（一次只看一层）

| 环节 | 核心指标 | 低了先查什么 |
|---|---|---|
| 曝光 | 展现量 | 标题关键词覆盖、类目是否放错、违规扣分 |
| 点击 | 点击率 | 主图首图、价格带是否偏离 |
| 转化 | 转化率 | 详情页模块、评价、SKU 是否缺属性 |
| 复购 | 复购率 | 品质、售后、老客维护 |

**定位纪律**：一次只动一个变量，改完观察一周期再动下一个。同时改标题又换主图，好了也不知道是谁的功劳。

### 第 3 步：归因（事实+依据）

- 好归因："点击率从 4.2% 掉到 2.1%，同期换了首图，依据是换图前后 7 天数据对比"
- 坏归因："我觉得是标题问题"（没有依据的归因都是玄学）
- 归因写不出来就写"待验证"，然后设计验证动作

### 第 4 步：改进行动（1-3 条，多了执行不了）

每条行动写清：改什么、怎么改、预期看什么指标、何时验证。

### 第 5 步：下期验证指标

复盘不闭环等于白做。每条行动配一个验证指标和验证时间，到期回头看。

## 4. 反模式

- ❌ 没有真实数据硬做归因——编数据比没数据危害大 10 倍
- ❌ 一次改 5 个地方——好了坏了都不知道是谁干的
- ❌ "我觉得""应该是"式归因——没有依据的归因都是玄学
- ❌ 复盘完不设验证指标——下期还是凭感觉
- ❌ 承诺"改完流量翻倍"——方法论只给方向，不给结果保证

## 5. 完整示例：一次周复盘

```markdown
# 周复盘：10 月第 2 周（马克杯）

## 数据快照
- 曝光：12000（上周 10000，+20%）
- 点击率：2.1%（上周 4.2%，-50%）
- 转化率：3.0%（上周 3.1%，基本持平）
- 退货率：5%（正常）

## 漏斗定位
点击率腰斩，曝光涨、转化持平 → 问题在点击环节（主图/价格带）。

## 归因
1. 点击率从 4.2% 掉到 2.1%，同期（10-08）换了首图，
   依据是换图前后 7 天点击率对比。
2. 价格带未变，排除价格因素。

## 改进行动（2 条）
1. 改什么：首图换回老版 / 怎么改：直接替换 / 看什么指标：点击率 / 何时验证：7 天后
2. 改什么：做一张新首图备选（场景版）/ 看什么指标：点击率 / 何时验证：老版恢复后测 7 天

## 下期验证指标
- 点击率回到 3.5%+ 视为恢复
```

## 6. 常见问题速查表

| 症状 | 先查 | 后查 |
|---|---|---|
| 有曝光没点击 | 主图首图、价格带 | 标题关键词 |
| 有点击没转化 | 详情页、评价、SKU | 客服响应 |
| 转化突然掉 | 是否违规扣分、差评 | 竞品降价 |
| 退货率高 | SKU 属性、详情页图文一致性 | 产品质量 |

## 7. 复盘会议议程（30 分钟版）

一个人也要走议程，别在脑子里"想一下"就完事：

1. **数据回顾**（5 分钟）：把本周数据和上周并排放，只读数不讨论
2. **异常定位**（10 分钟）：哪个环节掉了？用漏斗表定位到一层
3. **归因讨论**（10 分钟）：每个异常写一条归因，必须有依据，"我觉得"不算
4. **行动决策**（5 分钟）：定 1-3 条行动，每条写清改什么、看什么指标、何时验证

**纪律**：会上不许说"流量不好是因为大盘不好"——大盘不好时更要看自己哪里比同行差。

### 会议记录模板

```markdown
# 复盘会记录：<日期>
- 数据回顾：<本周 vs 上周，3 行以内>
- 异常定位：<掉的是哪一层>
- 归因：<事实+依据，1-2 条>
- 行动：<1-3 条，每条含"改什么/看什么指标/何时验证">
```

## 8. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 数据是真实的吗？→ 编的、估计的全部标"待核实"或删掉。
2. 归因有依据吗？→ "我觉得"开头的重写。
3. 行动 ≤3 条吗？→ 多了砍到 3 条。
4. 验证指标写了吗？→ 没写补上。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用一组模拟数据（曝光涨、点击跌）走一遍本 skill，检查漏斗定位、归因格式、行动清单是否达标。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、正文写清"复现输入 → 错误输出 → 期望输出"，提交到 https://github.com/lhg-plugs/lhg-taobao/issues。
